# Domain docs

This is a single-context repository. Before changing a relevant area, read
root `CONTEXT.md` if present and applicable ADRs under `docs/adr/`.

If they do not exist, proceed without them. Create `CONTEXT.md` only when a
project-specific term has been resolved; it is a glossary, not a spec or task
list. Create an ADR only for a consequential, non-obvious trade-off worth
preserving. Use the project's agreed vocabulary in specs and tickets.
